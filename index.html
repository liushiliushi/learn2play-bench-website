Evaluation protocol

How we evaluate agents

For each game template, we use one selected rule seed and run 3 independent trials. The leaderboard does not average over all possible seeds.

We report 5 episodes for normal games and 10 for challenge games. Scores are normalized using each game's reference ceiling, then averaged with weight 3 for challenge games and weight 1 for normal games.

Max

Average peak score across trials.

Mean

Average score across episodes.

LG Learning Gain

Improvement from early to late episodes.

LS Learning Slope

Fitted rate of score change across episodes.

Opus 5.5 evaluation details

OpenCode + Claude Opus 5.5 completed three trials on each of the 20 selected game instances. Of the 60 trials, 50 completed in their original sessions and seven resumed after API interruptions. Three incomplete trials were replaced with independent runs that added a generic reminder to finish each episode before advancing. No earlier trial results or game-specific hints were supplied to replacements. All retained terminal scores were verified. The same normalization, game weights, and scoring windows apply.

GPT-6 Astra evaluation details

GPT-6 Astra ranks second among the eleven OpenCode backbones on all four metrics: Max 76.25, Mean 56.07, LG +23.79, and LS +5.88. Twenty fixed game–seed instances each have three isolated trials of ten episodes: 600 verified terminal replays and 375 episodes in the manuscript’s scoring window. OpenCode uses the native Responses adapter with medium reasoning effort. These descriptive comparisons do not establish statistical significance.

Forty retained trials needed no continuation, eleven resumed their original sessions, and six needed only missing quit markers with unchanged game decisions and verified scores. Three protocol-invalid or interrupted trials were independently replaced; selection preceded replacement scores, and replacements received no prior trial experience. Original attempts remain archived. Seven retained trials precommitted multiple episodes before receiving feedback, reducing opportunities for sequential adaptation. All retained histories and terminal scores were independently verified. This cohort is separate from Codex; no matched Astra harness comparison is claimed.

Benchmark design

Key ideas behind Learn2Play Bench

Strong task performance can reflect prior knowledge. Novel game rules let us examine how agents acquire and reuse knowledge through interaction.

01

Discover, don't look up.

Novel, sometimes counterintuitive rules create unfamiliar situations. Agents see actions and feedback—not game source code or solutions.

02

Do agents improve with practice?

Agents play each game repeatedly and can use what they learned in earlier attempts. We measure whether their scores improve.

03

Can agents use what they learn in new situations?

In some games, the situation changes between attempts, but the rules stay the same. We test whether agents can still use what they learned.
